# hynix-exam-skills

AI 협업 개발에서 설계 판단과 실제 동작을 이해하고, 수동 테스트의 화면 왕복을 줄이는 범용 스킬 세 개입니다. 현재 비공개 개발 단계입니다. 실제 과제·코드·로그·시험 문항·개인 접속 정보는 포함하지 않습니다. 공식 배포물이나 사용 승인서가 아니며 최신 과제 지침을 우선합니다.

| 스킬 | 역할 |
|---|---|
| `skills/clarify-task-constraints/SKILL.md` | 담당자에게 핵심 업무 조건을 확인하고 실제 답을 설계·검증에 연결 |
| `skills/explain-as-you-build/SKILL.md` | 대안 장단점 비교와 사용자 선택, 처리 원리·검증·한계 기록 |
| `skills/guide-manual-tests/SKILL.md` | 허용된 터미널 검사와 사람의 화면 확인을 분리하고 테스트 안내 |

## 개발 흐름

- `main`: 기본 안내와 최종 검토한 버전.
- `prep/skills-v1`: 현재 세 스킬과 사용법을 다듬는 브랜치.
- 최종 검토 후 공개 전환과 `main` 대상 PR을 진행합니다. PR 생성과 병합은 별개입니다. 기본 브랜치를 Clone해서 사용할 계획이면 두 스킬이 `main`에 반영됐는지 확인해야 합니다.

## Codex CLI에서 읽기

설치 경로의 자동 인식을 전제하지 않습니다. 실제 복제 위치와 작업 폴더를 확인한 뒤 아래 세 파일의 정확한 경로를 지정해 읽게 합니다. 과제 작업 폴더는 유지합니다.

```text
복제한 저장소의 다음 세 파일을 읽고 현재 작업에 적용해줘.
skills/clarify-task-constraints/SKILL.md
skills/explain-as-you-build/SKILL.md
skills/guide-manual-tests/SKILL.md
먼저 명시된 조건과 가정을 구분하고, 중요한 미확인은 담당자에게 질문할 문장으로 준비해줘.
담당자의 실제 답을 받기 전에 핵심 설계와 그에 의존하는 구현을 확정하지 마.
중요한 설계는 대안의 장단점을 비교하고 내 선택 후 구현해줘.
핵심 변경만 짧게 설명하고 기존 작업 기록 하나에 근거를 모아줘.
화면 테스트 전에는 허용된 터미널 검사부터 수행해줘.
수동 안내는 앱 내 패널과 채팅 카드의 조건을 비교한 뒤 내 선택을 기다려줘.
```

앱 내 패널은 선택한 뒤 현재 앱 소스를 수정해 구현합니다. 스킬을 읽었다고 패널·자동 등록·브라우저 조작이 설치되는 것은 아닙니다. 패널의 실제 표시는 제공된 미리보기에서 확인해야 합니다. AI 사용이 금지된 평가 단계에는 적용을 종료합니다.

## 권장 순서

조건 확인 → 설계 대안과 사용자 선택 → 구현·설명 → 터미널 검사와 수동 테스트 순서입니다. 이미 받은 답은 재질문하지 않으며, 새 조건이 기존 선택의 전제를 바꿀 때만 해당 선택을 다시 검토합니다. 질문 초안·실제 전송·답 수신·부분 미해결을 구분합니다. 숨은 조건의 개수나 질문 여부의 공식 배점은 이 패키지가 보증하지 않습니다.

## 필요한 때의 짧은 요청

- `구현하기 전에 빠진 조건과 위험한 가정을 찾고 담당자에게 먼저 물을 질문 3개를 준비해줘.`
- `담당자 답을 반영해 확정 조건과 아직 답하지 않은 항목을 나누고 기존 설계에 미치는 영향을 알려줘.`
- `알고리즘을 작은 입력 하나로 따라가며 설명해줘. 보장하지 못하는 것도 알려줘.`
- `취소·중복 실행·처리 중 입력 변경의 현재 동작과 확인 근거를 점검해줘.`
- `터미널 확인 후 사람이 볼 테스트만 2~3개씩 준비해줘.`
- `수정한 부분과 영향받은 테스트만 다시 확인해줘.`
- `제출 전 코드와 기록을 대조하고 검증·미검증·남은 한계를 정리해줘.`

## 구성 원칙

특정 프레임워크·MCP·외부 API·브라우저 제어 도구는 필수 의존성이 아닙니다. 실제 관찰과 추정을 구별하고 사용자 판단·실행 결과를 꾸미지 않습니다. 공개 참고 자료는 explain-as-you-build의 references/sources.md에 정리되어 있습니다.

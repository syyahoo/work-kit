# hynix-exam-skills

AI 협업 개발에서 설계 판단과 실제 동작을 이해하고, 수동 테스트의 화면 왕복을 줄이는 범용 스킬 세 개입니다. 현재 비공개 개발 단계입니다. 실제 과제·코드·로그·시험 문항·개인 접속 정보는 포함하지 않습니다. 공식 배포물이나 사용 승인서가 아니며 최신 과제 지침을 우선합니다.

| 스킬 | 역할 |
|---|---|
| `skills/clarify-task-constraints/SKILL.md` | 담당자에게 핵심 업무 조건을 확인하고 실제 답을 설계·검증에 연결 |
| `skills/explain-as-you-build/SKILL.md` | 초기 설정·설치·실행, 대안 비교와 사용자 선택, 검증·판단 근거 기록 |
| `skills/guide-manual-tests/SKILL.md` | 허용된 터미널 검사와 사람의 화면 확인을 분리하고 테스트 안내 |

## 외부 붙여넣기 없이 시작하기

크롬의 시험 IDE 안에서 직접 타이핑하는 경우 긴 시작 프롬프트를 외울 필요가 없습니다. 루트의 `START.md`가 세 스킬을 읽고 환경 점검·조건 확인·선택 후 초기 셋업으로 연결합니다.

최종본이 **공개되고 main에 병합된 뒤**, 시험 IDE의 AI에 다음 한 문장을 직접 입력합니다.

```text
깃허브 syyahoo/hynix-exam-skills를 받아서 START.md대로 시작해.
```

AI가 제공된 터미널을 사용할 수 있으면 복제를 직접 수행하게 하는 요청입니다. 실제 허용·접속 성공을 보장하지는 않습니다. 현재 저장소는 비공개 개발 단계이므로 지금 익명으로 이 절차를 사용할 수는 없습니다. 시험에서 개인 GitHub 로그인이나 키 입력을 전제로 하지 않습니다.

터미널에 직접 입력하는 대안도 있습니다. 공개·main 병합 이후 기준입니다.

```bash
git clone https://github.com/syyahoo/hynix-exam-skills s
```

그다음 IDE의 AI에 `s/START.md 읽고 시작해.`라고 입력합니다. 로컬 PC 파일·클립보드·외부 사이트 열기는 필요하지 않습니다. 다운로드한 준비물 폴더와 과제 작업 폴더는 구분합니다.

비공개 개발 버전을 권한 있는 연습 환경에서 받을 때는 브랜치를 지정합니다.

```bash
git clone -b prep/skills-v1 https://github.com/syyahoo/hynix-exam-skills s
```

## 개발 흐름

- `main`: 기본 안내와 최종 검토한 버전.
- `prep/skills-v1`: 현재 세 스킬과 사용법을 다듬는 브랜치.
- 최종 검토 후 공개 전환과 `main` 대상 PR을 진행합니다. PR 생성과 병합은 별개입니다. 기본 브랜치를 Clone해서 사용할 계획이면 세 스킬이 `main`에 반영됐는지 확인해야 합니다.

## Codex CLI에서 읽기

설치 경로의 자동 인식을 전제하지 않습니다. 실제 복제 위치와 작업 폴더를 확인한 뒤 아래 세 파일의 정확한 경로를 지정해 읽게 합니다. 과제 작업 폴더는 유지합니다.

```text
복제한 저장소의 다음 세 파일을 읽고 현재 작업에 적용해줘.
skills/clarify-task-constraints/SKILL.md
skills/explain-as-you-build/SKILL.md
skills/guide-manual-tests/SKILL.md
시작할 때 실제 폴더·기존 코드·runtime·실행 도구·규정을 직접 점검해줘.
명시된 조건과 가정을 구분하고, 중요한 미확인은 담당자에게 질문할 문장으로 준비해줘.
담당자의 실제 답을 받기 전에 핵심 설계와 그에 의존하는 구현을 확정하지 마.
중요한 설계는 대안의 장단점을 비교하고 내 선택 후 구현해줘.
선택이 끝나면 다시 요청할 필요 없이 초기 설정 파일 작성·필요한 의존성 설치·서버 실행까지 직접 진행해줘.
명령 안내로 끝내지 말고 실제 포트·경로·현재 소스 반영을 확인하고, 허용된 첫 화면 확인까지 이어가줘.
핵심 변경만 짧게 설명하고 기존 작업 기록 하나에 근거를 모아줘.
최소 접속 준비 확인 뒤 실제 첫 화면을 먼저 확인하고 로직 검사·남은 수동 흐름을 이어가줘.
수동 안내는 앱 내 패널과 채팅 카드의 조건을 비교한 뒤 내 선택을 기다려줘.
```

앱 내 패널은 선택한 뒤 현재 앱 소스를 수정해 구현합니다. 스킬을 읽었다고 패널·자동 등록·브라우저 조작이 설치되는 것은 아닙니다. 패널의 실제 표시는 제공된 미리보기에서 확인해야 합니다. AI 사용이 금지된 평가 단계에는 적용을 종료합니다.

## 권장 순서

처음부터 환경을 점검하면서 조건 확인 → 설계 대안과 사용자 선택 → 초기 셋업·실제 첫 화면 확인 → 업무 구현·설명 → 로직 검사와 남은 수동 테스트 순서로 진행합니다. 이미 받은 답은 재질문하지 않으며, 새 조건이 기존 선택의 전제를 바꿀 때만 해당 선택을 다시 검토합니다. 질문 초안·실제 전송·답 수신·부분 미해결을 구분합니다. 숨은 조건의 개수나 질문 여부의 공식 배점은 이 패키지가 보증하지 않습니다.

## 공통 진행 상태와 근거 연결

작업 시작·재개·중요 단계 전환 때 기존 기록 하나에서 현재 단계, 대기 Q/R/D, 다음 행동을 확인합니다. 질문 Q → 조건 R → 사용자 선택 D·반영 코드 → 검사 T를 연결하고 필수 조건에 검사 근거가 빠졌는지 마무리에 확인합니다. 이전 기록의 단계·완료 표시를 새 조건·코드보다 우선하지 않습니다.

## 시작 단계의 초기 셋업과 첫 화면 확인

문서·자료만 있는 웹 IDE에서도 AI가 실제 작업 폴더·기존 설정·runtime·패키지 관리자·포트·규정을 점검합니다. 중요한 실행 설계가 이미 선택됐으면 재질문하지 않고 필요한 설정 파일 작성 → 의존성 설치 → 서버 실행 → 실제 포트·경로 접속 확인까지 직접 수행합니다. 선택 대기 중에는 독립 환경 점검을 계속하고 선택을 받으면 별도의 셋업 요청을 기다리지 않습니다. 기존 프로젝트·정상 실행 환경을 재사용하며 충돌 파일이나 데이터를 덮어쓰지 않습니다.

Docker와 직접 runtime 실행 중 현재 요구·환경에 맞는 방식을 선택합니다. Docker가 선택됐다면 client/server 연결 확인, 최소 Dockerfile·Compose 구성, 실제 이미지 빌드·컨테이너 실행을 수행하고 코드·이미지·포트·검사 실행 위치를 대조합니다. Docker 자체가 모든 과제의 필수 조건은 아닙니다.

초기 셋업 완료는 필요한 의존성 준비·서버 가동·현재 소스 접속·첫 화면 관찰이 실제 확인된 상태입니다. 설치 실패나 사용자 화면 관찰 대기를 완료로 쓰지 않으며, 실제 명령·실행 위치·시작/재시작/중지 방법·접속 경로·근거를 기존 작업 기록에 남깁니다. AI가 할 수 없는 최소 사용자 조치만 남기고 일반적인 설치·실행을 사용자에게 넘기지 않습니다. 셋업 완료는 업무 기능 완료와 별개입니다.

첫 의미 있는 화면과 핵심 화면 변경 직후에는 최소 서버 준비 확인 → 실제 브라우저 출력 확인 → 로직 검사 → 남은 수동 흐름으로 진행합니다. HTTP 200·캡처 파일 생성·단위검사만으로 화면 정상이라고 표시하지 않습니다. 자동 렌더링·캡처는 그 행위가 허용된 환경에서만 사용하며 자동 클릭·입력으로 확대하지 않습니다. 불명확하면 제공된 문의 경로로 확인하고, 그동안 사용자에게 IDE Browser에서 첫 화면 확인을 안내합니다. 자세한 절차는 explain-as-you-build의 `references/environment-checks.md`와 guide-manual-tests의 `references/render-checks.md`에 있습니다.

## 재사용 수동 테스트 패널

`skills/guide-manual-tests/assets/manual-panel/`에 외부 패키지가 필요 없는 브라우저 ESM 구성품이 있습니다. 패널을 선택한 뒤 현재 앱에 연결합니다. 준비·입력·조작·기대, 사용자 관찰 기록, 이전/다음·접기, CLI에 한 번에 전달할 요약과 JSON을 제공합니다. 앱을 자동 조작하거나 결과를 자동 판정하지 않습니다. 기록은 메모리만 사용하므로 새로고침 전에 필요한 요약을 확보합니다. 실제 연결 절차와 판본 비교는 해당 스킬의 `references/panel.md`를 따릅니다.

구성품 상태 검사는 해당 스킬 폴더에서 `node --test scripts/panel-smoke.test.mjs`로 실행할 수 있습니다. 업무 앱이나 시험 미리보기의 성공 검증과는 별개입니다.

## 필요한 때의 짧은 요청

- `시작 환경을 직접 점검하고, 필요한 선택 후 초기 설정·설치·실행·첫 화면 확인까지 진행해줘.`
- `구현하기 전에 빠진 조건과 위험한 가정을 찾고 담당자에게 먼저 물을 질문 3개를 준비해줘.`
- `담당자 답을 반영해 확정 조건과 아직 답하지 않은 항목을 나누고 기존 설계에 미치는 영향을 알려줘.`
- `알고리즘을 작은 입력 하나로 따라가며 설명해줘. 보장하지 못하는 것도 알려줘.`
- `취소·중복 실행·처리 중 입력 변경의 현재 동작과 확인 근거를 점검해줘.`
- `터미널 확인 후 사람이 볼 테스트만 2~3개씩 준비해줘.`
- `수정한 부분과 영향받은 테스트만 다시 확인해줘.`
- `제출 전 코드와 기록을 대조하고 검증·미검증·남은 한계를 정리해줘.`

## 구성 원칙

특정 프레임워크·MCP·외부 API·브라우저 제어 도구는 필수 의존성이 아닙니다. 실제 관찰과 추정을 구별하고 사용자 판단·실행 결과를 꾸미지 않습니다. 공개 참고 자료는 explain-as-you-build의 references/sources.md에 정리되어 있습니다.

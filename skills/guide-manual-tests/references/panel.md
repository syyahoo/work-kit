# 재사용 수동 테스트 패널

패널 방식을 사용자가 선택한 경우에만 현재 앱에 연결하라. 구성품을 준비했다는 사실은 현재 앱에 적용하기로 선택한 것이 아니다. 별도 브라우저 제어 API·MCP·패키지가 필요하지 않은 브라우저 ESM 모듈이다. 실제 제공 미리보기 지원은 별도 확인하라.

## 파일과 최소 연결

`assets/manual-panel/`의 panel.mjs·state.mjs·style.mjs를 **같은 폴더 구조로** 현재 앱에서 접근 가능한 소스/정적 파일 위치에 복사하라. 기존 파일을 덮어쓰지 말고 프레임워크의 모듈 처리 방식과 제출 요구를 확인하라. 문서·개발용 테스트 파일을 제품 번들에 무조건 넣지 마라.

```js
import { mountManualTestPanel } from './manual-panel/panel.mjs';
const panel = mountManualTestPanel({ plan: actualPlan });
// 실제 관련 코드·사례가 바뀌면 최신 값을 전달한다.
panel.updatePlan(updatedActualPlan);
// 메모리 객체를 읽는 것이며 자동 저장·전송은 아니다.
const report = panel.getReport();
const summary = panel.getSummary();
// 제출 조건상 제거가 필요하면 mount/import도 정리한다.
panel.destroy();
```

`actualPlan`은 `assets/manual-panel/example-plan.json`의 **형태만** 참고해 실제 요구·코드에서 채워라. placeholder 사례는 실제 검증이 아니다. 기본은 전용 host를 body에 추가하고 Shadow DOM으로 스타일을 격리한다. 필요하면 전용 `container`를 넘겨라. 앱 DOM·업무 자료를 읽거나 조작하지 않는다. 프레임워크에서는 기존 수명주기에서 한 번 mount하고 해제할 때 destroy하라. 매 렌더마다 중복 mount하지 마라.

## 계획 규격

- 계획: id, title, codeState(현재 커밋+미커밋 변경 또는 실제 파일 해시), cases 배열.
- 사례: id(T 식별자), title, requirements(R 식별자 배열), prepare, input, steps(문자열 배열), expected.
- 선택 codeRefs: 해당 사례에 관련된 `{"파일 경로":"실제 판본"}` 객체. 있으면 이 파일들 기준으로 판본을 비교하고, 없으면 계획 전체 codeState를 사용한다. codeState·codeRefs를 가짜 값으로 채우지 마라.
- 비어 있거나 unknown/미확인인 판본은 안내에는 사용할 수 있지만 관찰을 현재 코드의 검증 완료로 표시하지 않는다. 의미 없는 '최신' 같은 고정 문자열로 판본 비교를 무력화하지 마라.
- 같은 계획 id 안에서 사례를 갱신한다. 다른 프로젝트·계획은 새 인스턴스로 연다. 변경된 조건을 같은 ID의 무관한 새 검사로 재사용하지 마라.

## 사용자 동작과 결과 전달

패널은 접기·이전/다음 안내·준비/입력/조작/기대·관찰 입력·통과/실패/차단 기록·복사할 요약과 JSON을 제공한다. 이동·시간 경과는 판정하지 않는다. 관찰이나 차단 이유 없이 결과를 기록할 수 없다. 메모 작성만 한 상태와 기록 버튼을 누른 상태를 구분한다.

사용자가 **결과 요약**을 펼쳐 필요한 내용을 전달한다. 작업 환경 내 복사·붙여넣기가 허용되면 요약을 CLI에 한 번에 복사할 수 있다. 제한되면 사례 ID·결과·실제 관찰만 짧게 직접 입력하도록 안내하라. 긴 JSON이나 코드 판본을 외워 입력하게 하지 말고 AI가 가진 계획·판본에 연결하라. 자동 클립보드·다운로드·업무 버튼 조작·외부 전송·새 백엔드는 없다. 요약의 T와 R을 기존 정본에 연결하고 사용자 보고로 유지하라. JSON은 현재 상태와 과거 관찰 이력을 포함하지만 자동으로 WORKLOG에 저장되지 않는다. AI가 브라우저 메모리를 직접 읽거나 패널 입력을 자동 수신했다고 표현하지 마라.

기록은 메모리만 사용하므로 새로고침하면 사라진다는 안내를 제공한다. 필요한 기록은 새로고침·수정 전에 요약 또는 JSON으로 확보하도록 안내하라. `updatePlan`은 저장한 과거 이력을 보존하고, 작성 중 메모도 보존하되 결과를 다시 선택하게 한다. 바뀐 준비·입력·조작·기대·R·관련 코드 판본은 재확인 필요다. 사례별 codeRefs가 같으면 무관한 전체 코드 변경 때문에 그 기록을 무효화하지 않는다.

## 적용·확인·제출

- 핵심 버튼을 가리지 않는지, 접힌 상태와 원래 앱 레이아웃, 작은 화면, 키보드 조작을 현재 앱에서 확인하라. Shadow DOM도 배치 충돌까지 방지하지는 못한다.
- 패널은 앱 DOM 안에서 동작하므로 새 창·팝업·부모 IDE 접근·클립보드 권한을 요구하지 않는다. 제공 미리보기의 실제 앱 경로에서 연결하고 `.mjs`의 HTTP 상태·JavaScript MIME·상대 import와 앱의 CSP/iframe 스크립트 제한을 확인하라. 일반 Chrome이나 별도 합성 iframe에서의 성공을 실제 시험 미리보기·Docker 검증으로 확대하지 마라. 동작하지 않으면 실제 오류를 확인하고 앱의 기존 모듈 처리 방식으로 통합하거나 채팅 카드 대안을 논의하라. IDE·감독 설정을 바꾸지 마라.
- 구성품 자체 검사는 `node scripts/panel-smoke.test.mjs` 또는 `node --test scripts/panel-smoke.test.mjs`로 실행할 수 있다. 상태·기록 단위검사이며 실제 업무 UI·제공 미리보기의 성공 증거가 아니다.
- 노출은 현재 앱에 맞는 개발 모드/허용 경로로 선택하라. URL 파라미터는 접근 통제가 아니다. 과제·운영의 인증·데이터 규칙을 완화하지 마라.
- 제출 UI 변경이 곤란하면 채팅 카드로 전환을 논의하라. 숨김과 번들 제거는 다르다. 제거해야 하면 mount·import·경로·스타일까지 확인하라.
- 자동 판정·업무 폼 입력·버튼 클릭·DOM 스캔·이벤트 주입, IDE·감독 화면 수정과 제한 우회는 이 구성품의 역할이 아니다.

# 앱 내 수동 테스트 안내

사용자가 이 방식을 선택한 경우에만 앱 소스를 수정하라. Codex CLI의 파일 수정으로 구현할 수 있으며 브라우저 제어 API는 필요하지 않다. 실제 앱·제공 미리보기에서의 지원은 별도 확인하라.

## 작은 구성

- 앱과 함께 보이는 접이식 영역에 사례 ID·준비·입력·조작·기대 결과를 표시하라. 다음·이전은 **안내 항목만** 바꾸도록 하라.
- 관찰 메모와 미실행·통과·실패·차단 선택을 제공하라. 사용자가 기대와 비교해 선택한다는 점을 표시하라. 초깃값은 미실행이다.
- 사례와 코드 판본을 표시하고 관련 판본이 달라지면 옛 기록을 보존하되 재확인 필요로 구분하라. 무관한 변경까지 모든 결과를 무조건 무효화하지 마라.
- 작은 화면에서 핵심 버튼을 가리지 않도록 접기·스크롤·너비를 조정하라. 패널 켠 상태의 레이아웃 영향과 원래 앱 레이아웃을 구분해 검사하라.

## 넣지 않을 동작

- 업무 버튼 클릭·자동 입력·이벤트 발생·DOM 스캔으로 관찰 판정·시간 경과 후 자동 통과.
- 업무 자료 초기화·시험 데이터 덮어쓰기·미검증 샘플 일괄 주입.
- IDE·감독 화면·플랫폼 설치본 수정, 확장 설치, 제한된 창·탭 사용의 우회.
- 외부 API·원격 기록 전송·새 서버·MCP를 필수 의존성으로 추가.

## 기록과 제출

기존 합성 테스트 자료와 정본을 우선하라. 기록 수단은 가능한 가장 작은 것으로 선택하라. 기본은 사용자 관찰을 정본에 연결하는 것이며 이를 위해 새 백엔드를 만들지 마라. 앱 메모가 CLI에 자동 전달된다고 가정하지 마라. 필요한 결과를 한 번에 사용자에게 전달받거나 명시적으로 선택한 허용된 로컬 기록 경로를 사용하고 저장 실패 여부를 확인하라.

노출 방법(기존 개발 모드·별도 앱 경로 등)은 프로젝트에 맞춰 선택하라. URL 파라미터만으로 켜는 방법은 접근 통제가 아니다. 제출 UI 변경이 곤란하면 패널 방식을 재검토하라. 숨김과 번들 제거는 다르므로 제출에 필요한 상태를 확인하라. 인증·데이터 규칙을 테스트 편의 때문에 완화하지 마라.

# 실제 구현에 근거한 설명 연습

준비·출제·채점을 요청받을 때만 사용하라. 기본 작업에서는 설명·기록을 유지하고 퀴즈를 자동 시작하지 마라. 아래는 범용 연습 분류이며 실제 시험 문항·출제 빈도·공식 배점이 아니다.

## 연습 유형

| ID | 유형 | 확인할 내용 | 필요한 근거 |
|---|---|---|---|
| T1 | 상태 변화·예외·일관성 | 관련 예외에서 실제 상태와 영향 | 이벤트·저장·요청 코드와 재현 |
| T2 | 알고리즘·데이터 흐름 | 작은 입력의 선택·반복·종료·출력과 보장 한계 | 실제 함수·하위 호출·입력 예시 |
| T3 | 제약·규모 변화·개선 | 조건 변화에서 먼저 깨지는 부분과 대응 | 필수 제약·측정 또는 확인 계획 |
| T4 | 대안·AI 제안·본인 판단 | 비교안·실제 선택·이유·반영 결과 | 대화·설계 비교·변경·검증 |
| T5 | 검증·실패·수정 근거 | 입력·기대·관찰과 미확인 경계 | 같은 판본의 명령·실행·로그 |
| T6 | 요구사항·가정·범위 | 확정 요구·가정·우선순위와 영향 | README·담당자 답변·완료 기준 |

## 생성 절차

1. 현재 과제와 실제 코드, 사용자 선택·결정 기록, 검증 자료를 읽고 판본을 고정하라. 파일 해시 또는 커밋+작업 상태를 기록하라. 코드를 보지 못하면 가상 사례라고 명시하라.
2. 기본은 T1~T6 각 1문항의 연습용 6문항으로 준비하라. 실제 고정 구성이 아니다. 적용 불가능한 유형은 근거 있는 다른 유형으로 교체하고 이유를 기록하라. 부족한 자료를 답으로 만들어 넣지 마라.
3. 문항마다 중심 유형 하나, 실제 함수·로그·요구 등 근거 위치, 전제 점검, 필수 설명 2~3개, 대표 오류, 인정할 불확실성을 먼저 준비하라. 사용자에게 문제와 함께 내부 모범답안을 보여주지 마라.
4. 한 문항에 여러 독립 주제를 몰아넣지 마라. 후속 요구는 중심 유형과 연결된 최대 2개로 제한하라. 전문용어 암기보다 현재 결과의 구체 동작·이유·위험을 물어라.
5. 존재하지 않는 DB·인증·최적화·인간 개입을 전제로 묻지 마라. 검증이나 수정 기록이 없으면 그 사실과 다음 확인을 설명하는 문항으로 바꿀 수 있다. 기록 없음과 행위 부재를 단정적으로 동일시하지 마라.
6. 근거를 마련하려고 코드를 바꾸지 마라. 읽기 전용 출제 단계에서 새 실행이 필요하면 허용된 검사를 고르고, 판본·결과 변화가 문항에 영향을 주는지 대조하라.
7. 한 문제씩 내고 답을 기다린 뒤 채점·감점 근거·짧은 수정 답안을 제시하라. 현재 질문만 피드백하고 다음 문제의 답을 미리 공개하지 마라. 준비만 요청받으면 출제 계획과 필요한 자료까지만 제공하라.

## 문항 카드

`id, primary_type, type_evidence, artifact_state, evidence_locations, question, premise_check, expected_points, accepted_uncertainty, common_errors, rubric`를 기록하라. 제한시간은 사용자가 정한 값이 우선이며 기본 5분은 연습 설정이다.

질문 틀:
- T1: “[처리] 중 [관련 예외]가 생기면 어떤 상태가 남습니까? 실제 코드와 확인 범위를 설명하세요.”
- T2: “[작은 입력]이 [함수]를 거치는 순서와 선택 기준을 설명하세요. 무엇을 보장하지 못합니까?”
- T3: “[자원 감소/입력 증가] 때 취약해지는 부분과 영향, 대응·확인 방법은 무엇입니까?”
- T4: “AI 제안을 채택·수정·거절한 결정 하나의 대안과 장단점, 실제 선택 이유를 설명하세요.”
- T5: “[요구] 검증의 입력·기대·실제 결과와 확인하지 못한 경계를 설명하세요.”
- T6: “확정 요구와 추가 확인·가정을 구분하고, 가정이 틀릴 때의 영향을 설명하세요.”

## 연습용 10점 기준

- 실제 구현·기록과 일치 4점: 질문에 직접 답하고 실제 동작·선택 주체를 맞춘다.
- 원인·판단 연결 2점: 조건과 결과, 선택 이유를 설명한다.
- 구체 근거 2점: 실제 함수·입력·관찰·발언을 연결한다.
- 한계·다음 확인 2점: 보장과 미검증을 구분한다. 유형과 관계없는 개선을 강제하지 마라.

반점 단위를 허용하라. 같은 결함을 기계적으로 중복 감점하지 마라. 코드 줄번호 암기·전문용어·분량에 가점을 주지 마라. 질문 전제의 오류를 코드 근거로 바로잡는 답을 인정하라. 실제 실행 증거가 필요한 부분과 정확한 미검증 인정·검증 계획을 구분해 채점하라. AI 수정 사례가 없다는 이유만으로 T4를 0점 처리하지 마라.

6문항 원점수는 60점이며 필요하면 `원점수 / 60 × 100`으로 환산하라. 공식 합격선·등급으로 소개하지 마라. 향후 원문·독립 출처가 추가되면 근거와 유형을 갱신하라.

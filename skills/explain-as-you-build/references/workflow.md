# 공통 시작·단계·근거 연결

세 스킬은 현재 작업의 기록 하나를 공유한다. 기존 기록에 같은 내용이 있으면 표를 중복 생성하지 말고 필요한 열·식별자만 보완하라. 이 절차는 실행을 보장하는 hook이 아니다.

## 시작·재개와 짧은 상태

1. 실제 작업 폴더·최신 문제 지침·제공 도구·현재 코드·기존 기록을 대조하라. 이전 대화의 완료 표시를 현재 상태로 그대로 옮기지 마라.
2. 핵심 조건을 확인했는지, 중요한 설계를 실제로 선택했는지, 해당 코드의 검증이 있는지 순서대로 판단하라. 요청한 단계가 앞선 미확인을 해결했다는 뜻은 아니다.
3. 현재 단계와 막힌 의존 작업을 정하고 다음 행동 하나를 고르라. 중요한 시작·전환·재개 때만 다음 세 줄을 짧게 표시하고 정본을 갱신하라. 매 도구 호출·일반 질문마다 반복하지 마라. 읽기 전용 설명 요청에는 파일 기록을 만들지 마라.

> 단계: 조건 확인 / 설계 선택 / 구현 / 검증 / 마무리 중 현재 위치
> 대기: 실제 미해결 Q·R·D 식별자와 그 때문에 보류한 작업, 없으면 없음
> 다음: 지금 진행할 한 행동

조건이나 선택이 바뀌면 영향받은 부분만 이전 단계로 돌아간다. 전체 작업을 처음부터 다시 승인받지 마라. 의존하지 않는 조사·기존 검사·확정 범위 구현은 계속할 수 있다.

## 단계가 바뀌는 조건

| 다음 단계 | 필요한 확인 | 미충족일 때 |
|---|---|---|
| 설계 선택 | 해당 결정의 목표·필수 제약·업무 우선순위·규모 등 중요한 전제가 확인됨 | 조건 확인으로 연결, 영향 없는 다른 결정은 진행 가능 |
| 구현 | 중요한 해당 설계에 실제 사용자 선택 또는 명시적 판단 위임이 있음 | 선택을 기다리고 관련 구현만 보류 |
| 검증 | 확인할 R·변경 코드·기대 결과·검사 방법이 식별됨 | 검증을 준비하고 미실행으로 유지 |
| 마무리 | 필수 R마다 현재 검증 상태·근거·남은 한계가 확인됨 | 빈 연결·옛 결과·미검증을 표시하고 완료를 과장하지 않음 |

모든 상상 가능한 질문에 답을 받아야 한다는 뜻은 아니다. 낮은 위험의 가정은 영향·범위·미확인을 표시할 수 있으나, 핵심 제약을 몰래 가정으로 우회하지 마라. 마무리 단계와 모든 요구 충족은 다르다. 실패·미완료를 포함한 현황 정리도 가능하다.

## 조건 → 선택 → 코드 → 검사의 연결

- 질문은 Q1, 확인할 요구·조건은 R1, 중요한 선택은 D1, 검사는 T1처럼 짧고 안정적인 ID를 사용하라. 기존 ID 체계가 있으면 유지하고 기록을 합칠 때 충돌만 해소하라. 삭제·변경된 항목의 ID를 다른 뜻으로 재사용하지 마라.
- Q는 실제로 물을 필요가 있을 때만 만든다. 문제문에 이미 있는 R에는 문제문 출처를 연결하고 가상의 질문 이력을 만들지 마라.
- 기존 정본에 다음 대응을 한 행씩 연결하라. 양방향 중복 표를 만들지 마라.

| R·조건 상태 | 완료 기준·출처(Q 또는 문제문 위치) | D·실제 선택과 반영 코드 | T·검사와 증거 종류 | 현재 확인 상태·미해결 |
|---|---|---|---|---|

조건 상태: 명시 / 담당자 확인 / 사용자 정책 결정 / 가정 / 미확인 / 충돌.
검증 상태: 미검증 / 일부 검증 / 검증됨 / 재확인 필요 / 해당 없음(이유).

Q 답 수신, D 선택, 코드 구현, T 실행은 서로 다른 사건이다. 하나를 끝냈다고 다음 사건까지 완료로 쓰지 마라. T에는 대상 R, 입력·기대·관찰·절차·코드 판본·출처를 남긴다. 한 T가 여러 R을 확인하거나 한 R에 여러 T가 필요할 수 있다. 자동 검사와 사용자 화면 관찰은 별도 근거로 유지한다.

새 답으로 R 의미가 바뀌면 해당 R의 D·코드·T만 검토하라. 관련 코드·기대값이 바뀐 옛 T는 재확인 필요로 남기고 이력을 보존하라. 관련 없는 변경 때문에 모든 결과를 무효화하지 마라. 새 기대값을 통과시키기 위해 과거 실패를 지우지 마라.

## 마무리의 작은 누락 점검

필수 R의 검사 연결 누락, 선택 전 구현, 담당자 답을 넘은 가정, 일부 답의 전체 완료 처리, 미실행·옛 판본의 통과, 사용자 관찰을 AI 실행으로 바꾼 기록을 확인하라. 요구와 무관한 D·T를 채우기 위해 추가 작업을 만들지 마라. 체크 개수·통과 개수만으로 업무 정확성이나 공식 점수를 주장하지 마라.

# 작업 이해와 근거

기존 기록이 있으면 필요한 항목만 통합한다. 과제가 정한 문서·제출 형식을 우선한다. 대괄호는 지침이며 실제 기록이 아니다.

## 목표와 완료 조건

- 작업 폴더·사용자·목표:
- 입력·출력·필수 제약·제출 경로:
- 확인한 정책과 출처 / 임시 가정·열린 질문:

## 담당자에게 확인한 조건

[질문이 필요할 때만 행을 추가한다. 문제문에 명시 / 담당자 확인 / 사용자 설계 선택 / 임시 가정 / 미확인 / 충돌을 구분한다.]

| ID·상태 | 질문·확인할 조건 | 실제 답·출처 | 해석·남은 미확인 | 설계·완료 기준·검증 영향 |
|---|---|---|---|---|

질문 작성·실제 전송·답 수신·일부 미해결을 구분한다. 담당자 답이 없는 칸은 비워두거나 답 없음으로 표시한다. 기존 선택의 전제를 바꾸는 답은 관련 선택의 재검토로 연결한다.

## 조건·설계·검사 연결

[기존 요구 표가 있으면 아래 열만 보완하고 같은 R을 중복 작성하지 않는다.]

| R·조건 상태 | 완료 기준·출처(Q 또는 문제문 위치) | D·실제 선택과 반영 코드 | T·검사와 증거 종류 | 현재 확인 상태·미해결 |
|---|---|---|---|---|

질문(Q)·조건(R)·선택(D)·검사(T)의 ID를 유지한다. 새 답·관련 코드 변경이 영향을 주는 기존 T는 재확인 필요로 남긴다. 질문 완료·구현 완료·검증 완료를 구분한다.

## 중요한 설계 선택

| 결정할 문제 | 실행 가능한 대안과 장단점 | AI 추천과 근거 | 사용자 선택·실제 발언 | 사용자 이유 또는 미제공 | 상태·반영 위치·검증 |
|---|---|---|---|---|---|

선택 전에는 '선택 대기'로 기록한다. AI 추천은 사용자 선택이 아니다. 이유 없이 선택했다면 이유 미제공으로 남기고, AI가 설명한 이유와 섞지 않는다. 기존 선택은 전제가 바뀌지 않는 한 다시 묻지 않는다.

## 중요한 사건 이력

[중요 변경·결정·검증 때만 짧게 추가한다. 기존 정본을 교체하지 않는다. 관련 없는 항목은 생략하거나 이유와 함께 해당 없음으로 표시한다.]

- 처리 원리와 예시 / 보장과 한계:
- 검증 조건·기대·관찰·명령/절차·증거 종류:
- 실패·수정·미검증 / 개선 우선순위와 다음 확인:

## 검증 증거

| 요구·사건 | 입력·조건과 기대 | 관찰 결과 | 절차·증거 위치·종류 | 코드 상태·현재 유효성 |
|---|---|---|---|---|

미실행·skip·추정·옛 코드 결과는 그대로 쓴다. 같은 내용은 사건 이력에서 행을 참조하고 중복 작성하지 않는다.
